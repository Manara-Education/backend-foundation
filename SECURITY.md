# Security Policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.** A public issue
tells everyone about the flaw before there is a fix.

**Use GitHub Security Advisories**: the *Security* tab → *Report a
vulnerability*. This creates a private thread visible only to the maintainers,
and it is the channel we monitor.

A dedicated security mailbox is not published here on purpose. Advertising an
address that turns out to be unmonitored is worse than advertising none — a
reporter does the right thing and the report goes nowhere. If you cannot use
GitHub Advisories, open a public issue containing **no details at all**, just a
request for a private contact, and a maintainer will reach out.

Please include what you can: what the issue is, how to reproduce it, which
version or commit you saw it on, and what an attacker could achieve with it.

### What to expect

| | |
|---|---|
| First response | within 3 working days |
| Assessment and plan | within 7 working days |
| Fix for a confirmed critical issue | as quickly as we can, ahead of feature work |

We will tell you what we found, when it is fixed, and credit you in the release
notes if you would like that.

## Scope

This repository is the **backend API** of the Manara education platform. Also in scope:

- `Manara-Education/backend-foundation`
- `Manara-Education/frontend-foundation`
- the production deployment at https://manara-edu.com

Out of scope: findings that require an already-compromised device, social
engineering of staff or users, denial of service by volume alone, and reports
generated by a scanner with no demonstrated impact.

## Supported versions

Only the **latest release** is supported. Fixes go into a new release rather
than being backported.

## What we already do

Not a claim of completeness — it is here so a reporter does not spend time on
something already handled:

- **Authentication** is server-side sessions in Redis with `HttpOnly` cookies
  and CSRF tokens, not bearer tokens in browser storage.
- **Rate limiting** on login, registration, OTP verification, password reset and
  uploads, backed by Redis so it survives a restart.
- **OTP codes** are single-use, expire, and are burned after a small number of
  failed attempts, so a six-digit code cannot be enumerated.
- **No card data is accepted.** There is no payment provider integrated, so
  nothing card-shaped is transmitted to or stored on our servers.
- **Uploads** are validated by decoding the bytes as an image, not by trusting a
  filename or a `Content-Type` header, and are stored under generated names.
- **The API documentation is disabled in production** — no OpenAPI document and
  no Swagger console.
- **The database and Redis are not reachable from the internet**: they publish no
  ports and sit on an internal Docker network with no route out.
- **Dependencies** are updated weekly by Dependabot; security advisories are
  raised individually and reviewed by a human rather than auto-merged.
